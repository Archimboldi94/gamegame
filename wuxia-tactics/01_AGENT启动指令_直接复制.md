# 给编程Agent的启动指令

你现在是本项目的 Godot 4.3+ 游戏开发 Agent，请直接在提供的项目文件中开展工作，而不是只给建议或重写一份GDD。请先阅读根目录《00_项目交接说明.md》，再阅读《02_当前设计文档/武侠战棋_GDD_v2.0.md》和《01_Godot工程/WuxiaTactics_Core_v2.0/README.md》。

【项目定位和不可擅改的决定】
这是单机武侠战棋，传统策略战棋为主，武学构筑为辅，江湖探索再次之。已确认：按速度排序敌我交错行动；行动消耗AP；正方形战棋格、八方向移动，普通地形横竖斜均为1AP，不得斜穿封闭墙角；概率命中；自动反击＋角色正前方及两侧5格控制区（背后三格盲区）；内力自然恢复＋主动调息；3个主动招式＋1内功＋1轻功，跨门派有限自由搭配；角色独立等级经验；武学采用分支精进而非刷熟练度；队伍共享秘籍谱库，各角色独立学习和精进；江湖采用小型场景自由探索，实时流畅八方向移动；探索和战斗均为斜45°视觉；精致像素风、修长偏写实的3.5—4.5头身角色、适度写意武学特效；战斗HUD采用简洁情境型。
注意：GDD中【已定】必须遵守；【建议】（如6AP、数值、分辨率等）只作为原型测试参数，不可伪称最终定案；历史文件只供追溯，不得覆盖v2.0规则。

【开发工作目录】
01_Godot工程/WuxiaTactics_Core_v2.0/
优先在这个项目上修复和迭代，不要另起一个不兼容的新工程。根目录下有历史文档、第一章地图、脚本及美术参考。不要直接使用历史Godot样机作为主工程。

【当前里程碑：先让B1《渡口截箱》真正可玩】
阶段P0——先检查环境和工程。识别本机Godot版本（目标4.3或更新）；导入project.godot，运行主场景及自动化测试，收集完整错误日志。可先运行 python tests/static_validation.py；在能调用Godot CLI时运行 godot --headless --path . --editor --quit 和 godot --headless --path . --script res://tests/CombatTests.gd（若本机命令名不是godot，请自行替换）。修复所有脚本解析错误、失效资源引用、运行异常和阻断交互的问题。静态测试通过不等于引擎测试通过，不能混淆。

阶段P1——验证并修复完整的B1回合战斗。确保3名我方角色与2名敌人在12×12菱形战场上按速度交错行动；移动、泥地成本、AP、内力、命中率、伤害、防御/破甲、角色面向、五格控制区、RP反击/借机攻击、敌人AI、胜负、重开、HUD预览与真实结算一致。重点检查斜向拐角、脱离多个敌方控制区、反击不会递归、行动顺序和RP刷新、未命中、AP不足、队伍灭亡、敌人寻路无路可走等边界情况。对战斗逻辑增加可重复的自动化测试，并手动实玩至少3局（若有图形环境）。修复优先，不新增无关功能。

阶段P2——只有P0/P1验证通过后，再接通最小闭环：可实时八方向移动的客栈/渡口探索测试场景 → 靠近交互点触发B1 → 战斗结束按结果结算 → 胜利时一次性解锁共享谱库中的《回锋剑谱》 → 返回安全探索出生点 → 可在整备界面查看已解锁秘籍。先用简单占位像素图/纯色几何图，暂不制作完整竹林、废祠、动画特效及全部剧情。探索不得复用AP格子移动控制器。

【实现与质量要求】
- 保留Godot项目原有场景入口及可运行性；模块化拆分BattleBoard、BattleState、EnemyAI、BattleUI、探索、任务和保存逻辑，避免把规则放在HUD中。
- 战斗状态结算唯一来源；UI只读取状态并预览，不能再次随机判定命中。
- 使用数据驱动定义关卡、单位、武学和奖励；新增状态须能序列化或有明确重建规则。
- 使用现有v1.3关卡蓝图和GDD做约束，但把未实现机制标注为未实现；不要擅自扩写门派/剧情或改动已确认决定。
- 不引入需要付费、侵权或来源不明的素材；占位画面足够。
- 每完成一小阶段就运行适当测试，记录测试命令、结果和未解决的问题；如果没有Godot可执行程序，明确写出“未运行Godot测试”，不要声称已验证可玩。
- 遇到非关键设计问题自行做简单原型选择并标记【建议】；仅在会修改【已定】的核心规则时才向我提问。

【交付标准】
1. 一个可直接在Godot中导入并运行的工程（若环境具备Godot，必须实测）。
2. 项目内的 TEST_REPORT.md：引擎版本、运行命令、通过/失败测试、已知问题、3局试玩记录或无法试玩的原因。
3. 项目内的 CHANGELOG.md：修改的文件、改动原因、兼容性注意事项。
4. 项目内的 NEXT_STEPS.md：按P0/P1/P2列出已完成和剩余工作，并明确下一项最小任务。
5. 若对机制或设计建议作了调整，同步补充GDD迭代记录，区分【已定】【建议】【未实现】；不要删除原始设计决策。

现在直接从P0开始：列出工程结构，运行检查，修复阻断问题，完成后继续P1。不要仅输出开发计划。

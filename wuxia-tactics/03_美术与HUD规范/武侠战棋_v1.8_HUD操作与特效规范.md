# 《武侠战棋》HUD与武学特效规范 v1.8

**已确定**：武学特效适度写意（B）；**未定**：HUD形态及输入方式，本文按原型建议设计。


### 23.1 视觉强度【已定：B 适度写意】

- **【已定】**武学特效采用适度写意：刀光、剑气、轻功残影、内力波纹可明确辨认，但不采用大面积持续遮盖地图的高武光污染效果；保留克制的武侠人物动作。
- **【已定的既有逻辑】**招式所及格子、命中和伤害、击退轨迹、AP与内力消耗由战斗规则层确定，特效不能增加攻击范围、越墙、追加伤害或再进行命中随机判定。
- **【建议】**特效素材强调有限色组、锋利像素轮廓、短停留时间，尽量与前文人物及地形的低饱和精致像素风一致。
- **【建议】**玩家可以开启“快速演出”，并设置低闪光/减少震动；只缩短展示时间，不改变规则事件及概率结果。

### 23.2 武学特效分层、时序与视觉语法【建议】

| 类别 | 视觉形式 | 原型建议时长 | 不得误导的规则 |
|---|---|---|---|
| 普通剑法 | 单色短弧、刀剑高光、收势 | 0.30—0.50s | 武器划过不代表多个目标均受到攻击 |
| 破风剑 | 3格方向上的细长青白剑气，格心逐段亮起 | 0.40—0.70s | 被阻挡处终止；不得暗示第4格命中 |
| 震山掌 | 贴近出掌点的短暂气纹与冲击圈 | 0.30—0.60s | 仅实际被击退者显示确定落点 |
| 燕行步 | 起点残影、短风痕、可落点轻闪 | 0.25—0.50s | 不是穿墙瞬移；越障限制不变 |
| 截脉指 | 单束微亮指光、脉络符纹与AP下降状态符号 | 0.20—0.40s | 若未命中则不得显示封招生效 |
| 归元诀/护势 | 贴身聚气及HUD状态/资源变化 | 0.30—0.60s | 内力回复不是气血回复；护势不等于无敌 |

**演出信息优先级**：玩家当前位置和目标位置 ＞ 已提交的AP、内力消耗与结果 ＞ 路径/控制区风险标记 ＞ 局部特效 ＞ 装饰性粒子。相机震动不应使HUD随之摇晃；快速闪烁和满屏白闪默认不用。

**规则与演出分离**： `BattleResolver`一次生成确定的`CombatEvent[]`，其后`CombatPresentation`只读播放。命中/未命中、伤害、AP/RP及状态不因跳过动画而改变，反击不能通过动画递归触发。

### 23.3 战斗HUD设计目标与优先级【布局建议】

界面要让玩家在施放武功前回答五个问题：**轮到谁、还剩多少AP/内力、能到哪里、会打中谁、移动或攻击后会受到什么威胁。**

| 信息等级 | 内容 | 常驻策略 |
|---|---|---|
| P0：必须实时可见 | 当前角色、队列先后、AP、内力、气血、技能花费、目标命中率、命中伤害 | 队列与资源常驻，具体目标数据在预览时展开 |
| P0：危险路径警示 | 控制区、离区借机攻击风险、RP是否仍可用、地形不可通行 | 路径或敌人悬停时出现明确图标与线框 |
| P1：行动决策支持 | 武学攻击范围、精进分支、护势/气脉受阻、关卡胜负条件 | 情境面板或展开详情 |
| P2：可收起 | 日志、长技能说明、历史伤害、系统设置 | 悬停、快捷键或菜单按需打开 |

**数值口径**：目标预览中“预计伤害12”必须标为“**命中后伤害12**”；命中率75%表示本次攻击成功机会，而非固定扣12血。击退、点穴等命中后效果应注明“命中后触发”。若同时可能触发反击，明确显示“目标可反击（RP 1/1）”或“离区可能遭借机攻击”。

### 23.4 主界面布局【建议，参考设计分辨率1280×720】

**注意**：前文640×360是【建议的像素世界渲染基准】，这里1280×720是**HUD布局设计参考画布**；两者不等于已定项目分辨率。在低分辨率背景上可考虑更清楚的UI文本呈现方案，不直接将中文小字压缩到难读的像素字。

```text
┌─────────────────────────────────────────────────────────────────────────────────┐
│ [轮次 03] [当前剑客] → [敌刺客] → [枪客] → [敌刀兵] → [拳师] ...  [任务] [菜单]│ 顶部
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                │
│              地形、角色、路径、高亮菱形格（主战斗视野）                       │
│                                                                                │
│  [可选迷你日志]                                      ┌───────────────────┐ │
│                                                      │ 命中率 75%        │ │
│         移动/技能路径与借机风险视觉提示               │ 命中后伤害 12     │ │
│                                                      │ AP -4，内力 -3    │ │
│                                                      │ 目标RP及状态      │ │
│                                                      └───────────────────┘ │
├─────────────────────────────────────────────────────────────────────────────────┤
│ [当前角色 气血/内力/AP/RP] │ [普攻] [武1] [武2] [武3] [轻功] [防御] [调息] [物品] │
│ [头像、状态、兵器]      │ [技能提示/剩余AP预测]                 [结束回合]      │ 底部
└─────────────────────────────────────────────────────────────────────────────────┘
```

**分区建议**：顶部高度约64—80px，显示队列和轮次；底部约120—150px，左侧人物状态、中央行动指令、右侧结束操作；战场区域保留主要画面。右侧目标预览为**情境浮层**，没有目标时收起；必须避开重要角色和敌人位置，必要时可移动到左侧或缩成摘要。

**操作栏命令**（原型）：普通攻击、主动招式1/2/3、轻功、普通防御、调息、物品、结束回合。**移动不强制占一个按钮**：正常状态下鼠标悬停合法格即可预览，点击移动。已确定的内功作为被动能力显示在人物状态或技能详情里，不设置误导性的“主动内功按钮”。

**反应机会**：RP单独标注，不混入AP条；`1/1`表示本轮仍可自动反击/借机攻击，`0/1`表示本轮反应已经用尽。队列头像可在需要时用简短标记提示RP状态。

### 23.5 输入方式与操作状态机【建议：优先鼠标＋键盘】

首版以PC鼠标为首要交互方式；是否同步适配手柄尚未由用户决定。**探索WASD移动已作为原型建议存在，不意味着战棋模式也必须使用WASD移动人物。**

```text
WAIT_TURN（等待我方行动）
  └─ start_player_turn → IDLE（当前角色可操作）
IDLE
  ├─ hover_reachable_tile → MOVE_PREVIEW
  ├─ select_basic_attack/skill/qinggong → TARGET_PREVIEW
  ├─ hover_unit → INSPECT_ONLY
  └─ end_turn → WAIT_TURN
MOVE_PREVIEW
  ├─ hover tile → 更新路径、逐格AP、借机风险
  ├─ click safe tile → RESOLVING（结算移动）
  ├─ click hazardous tile → RISK_CONFIRM（仅风险路径二次确认）
  └─ cancel → IDLE
TARGET_PREVIEW
  ├─ hover legal target → 命中率、命中伤害、AP/内力、状态和反击可能性
  ├─ click legal target → RESOLVING
  └─ cancel → IDLE
RISK_CONFIRM
  ├─ confirm → RESOLVING
  └─ cancel → MOVE_PREVIEW
RESOLVING
  └─ 规则先结算＋演出结束 → IDLE / WAIT_TURN / BATTLE_END
```

**风险路段定义【建议】**：路径会脱离某名有RP且可合法借机攻击的敌人控制区时，标记该步和预计触发者，**仅在提交有风险的路径时要求再确认一次**；安全移动与普通攻击不增加额外确认步骤。攻击失败仍消耗已支付资源；发生随机性、敌人反应或状态效果的行为提交后**不能撤销**。

**待机结束按钮行为【建议】**：只结束当前角色行动，不自动结束整个阵营回合；因为战斗使用**速度排序、敌我交错行动**，不能使用“我方回合结束”造成概念误导。

### 23.6 鼠标与键盘操作表【建议】

| 输入 | 行为 | 限制/反馈 |
|---|---|---|
| 鼠标悬停地面格 | 预览移动路径、AP和借机风险 | 仅轮到我方角色时可提交 |
| 鼠标左键地面格 | 执行合法移动；危险路径先提示确认 | 不能穿过实体障碍或封闭斜角 |
| 鼠标左键技能按钮 | 选中招式并进入范围预览 | AP/内力不足时不可执行，显示原因 |
| 鼠标左键合法目标 | 提交技能并播放结果 | 不再进行一轮独立的命中骰 |
| 鼠标右键 / Esc | 取消预览、返回上一层 | 不回滚已提交战斗事件 |
| 数字键1—3 | 选中主动招式1—3 | 显示与槽位一致的快捷键 |
| `Q` | 普通攻击 | 若键位冲突允许重绑 |
| `E` | 轻功 | 与探索模式交互键不同场景使用 |
| `F` | 普通防御 | 无法执行时提示AP不足 |
| `R` | 调息 | 受每次行动调息次数限制 |
| `Tab` | 显示下一行动单位详情 | 只查看，不变更行动队列 |
| `Space` | 结束当前单位行动 | 可选确认剩余AP，默认不强制弹窗 |
| 鼠标滚轮/中键拖动 | 战棋镜头缩放/平移 | 避开HUD输入区，防止误触 |

**注意**：快捷键仅属原型建议，需提供在设置里重绑定的空间。`E`在江湖探索用于交互，在独立战棋场景用于轻功，不会同时响应。

### 23.7 详细信息预览规则【建议】

**移动路径预览**展示：起点、途经格、落点、逐步累计AP、各格地形成本、是否穿越合法斜角、每个可能的控制区脱离事件、潜在借机攻击者和RP。若有多名敌人，按规则层返回的实际可触发次序显示风险，而不是按特效画面猜测触发者。

**攻击预览**展示：武学名称、AP/内力成本、施术者本回合剩余资源、技能实际目标区域、命中率组成、**命中后的确定性伤害**、附加状态、目标护甲和护势变化。若是多目标招式，则提供目标逐个命中率/命中后伤害，避免把一个群体命中率误表示为所有目标共享的单次随机事件；“逐目标是否独立掷命中骰”属于待明确的后续规则。

**危险信息优先于华丽特效**：技能预计伤害、AP和控制区图标必须有足够文字对比度；未获得技能精进的选项不可因美术过亮而看起来能使用；角色被屋檐遮挡时，人物脚底圈和实际格子位置要可读。

### 23.8 HUD与特效的分层架构（Godot 4.x建议）

```text
BattleScene (Node2D)
├─ BattleGridLogic (Node)                 # 规则层：仅逻辑格、路径、伤害、RP等
├─ BattleWorld (Node2D)
│  ├─ Ground (TileMapLayer)
│  ├─ BattlefieldMarkers (Node2D)         # 格子范围与控制区
│  ├─ UnitsYSort (Node2D)                 # 角色脚底锚点和深度
│  ├─ VFXWorld (Node2D)                   # 局部剑气、残影与掌风
│  └─ FloatingCombatText (Node2D)        # 伤害、闪避、状态浮字
├─ BattleHUD (CanvasLayer)               # 固定在屏幕上的信息层
│  └─ HUDRoot (Control)
│     ├─ TopBar (MarginContainer)
│     │  ├─ TurnOrder (HBoxContainer)
│     │  └─ Objectives (Control)
│     ├─ ActiveUnitPanel (Control)
│     ├─ CommandBar (HBoxContainer)
│     ├─ ContextPreview (PanelContainer)
│     ├─ MiniCombatLog (Control)
│     ├─ TooltipLayer (Control)
│     └─ PauseMenu (Control)
└─ BattleInputController (Node)           # 命令模式、输入与取消
```

Godot的`CanvasLayer`适合显示独立于场景变换的HUD，`Control`的锚点与`Container`适合处理不同窗口比例和自动布局；鼠标不需拦截的透明UI覆盖区域要使用适当的`mouse_filter`（如IGNORE），避免遮挡对格子的点击。**不要**让`UI`调用角色动画来决定命中伤害；UI只向规则层提交命令与预览请求。

**数据流【建议】**：`BattleInputController`→`BattleCommandValidator`（成本、路径、RP、射程）→`BattleResolver`（状态及随机事件）→`CombatEvent[]`→`CombatPresentation`与`HUDViewModel`。预览和正式结算应共享同一套**规则计算函数**，仅预览不掷骰；显示的命中率来源必须与真正投骰的参数一致。

**可维护信号【建议】**：`turn_started`, `active_unit_changed`, `ap_changed`, `inner_power_changed`, `rp_changed`, `path_preview_changed`, `skill_preview_changed`, `command_committed`, `combat_events_resolved`, `battle_ended`。目标列表更新的频度需要节流或缓存，以免鼠标移动时反复全图计算。

### 23.9 UI可读性与辅助选项【建议】

- 不只依靠颜色表达敌我、控制区与伤害类型；关键状态配备形状、图标与文字。
- 支持界面缩放/文字大小调节；中文技能名与说明不应被固定宽度截断到无法辨认。
- 当前行动角色与下一位行动者必须明确区分；当速度变化只在下一轮生效时，队列预览要按既定轮次规则一致更新。
- 玩家主动开启的“显示危险范围”覆盖层不得隐藏当前行动格、武学AOE区域；需要定义覆盖层透明度和层级优先级。
- 相机震动可关闭，VFX演出可加速；低闪光模式减少强光闪烁，不改变游戏机制。
- 任务面板默认精简为一行目标，完整任务描述点击展开，不长期占据战场右侧。
- 战场缩放或角色被屋檐遮挡时，仍能选中真实逻辑格，且危险格标注不离开对应格子。

### 23.10 B1「渡口截箱」HUD教学与验收【建议】

按玩家第一次进入B1的顺序递进教学，而非一次弹出长教程：

1. 进入战斗时，顶部队列显示我方剑客与下一位敌方角色，并提示“按速度顺序行动”。
2. 鼠标移动到合法格，显示预计AP成本和移动路径；越过障碍或走封闭斜角被阻止。
3. 悬停敌人后出现“普通攻击命中率”“命中后伤害”，若具RP和反击条件，出现反击风险标记。
4. 在敌人前侧控制区内移动到外部，路径正确显示借机攻击警示；安全轻功则不显示错误警示。
5. 玩家使用一次技能，确认战术HUD资源扣除，与动画结果一致；使用失败不应错误扣除资源。
6. 玩家主动结束行动，队列切换到下一名单位；敌我交错，不出现“等待我方全部行动完”的错误提示。
7. 战斗演出期间阻止重复提交同一指令；被跳过的动画不再次生成伤害。
8. 在640×360像素世界画面和1080p显示输出下测试中文文字可辨，技能悬停不遮挡目标脚底圈。

**必须通过的边界测试**：反击触发RP已用尽、背后盲区不触发反击、危险路径确认取消不扣AP、攻击命中概率显示和规则一致、目标超出范围按钮不允许提交、不同斜视相机缩放下鼠标选择格子正确。

### 23.11 分步实现与版本风险【建议】

| 优先级 | 功能包 | 验收重点 |
|---|---|---|
| P0 | 顶部队列＋当前角色HP、AP、内力、RP | 不误写阵营回合，不隐藏关键资源 |
| P0 | 地图选格、移动路径、技能AOE显示 | 范围与逻辑格完全一致 |
| P0 | 鼠标基础操作、右键撤销、战斗中输入锁定 | 不重复提交命令 |
| P0 | 命中率与命中后伤害预览 | 实际公式一致，不误导为必中 |
| P0 | 前侧5格控制区／3格盲区／反应警示 | 正确显示合法危险步骤 |
| P1 | 完整动作快捷键、状态说明、日志 | 降低交互次数，信息可追溯 |
| P1 | 适度写意武学特效播放层 | 特效不覆盖P0信息 |
| P2 | 可调整位置的预览浮层、VFX加速/低闪光、手柄导航 | 体验完善；不能提前压过战斗机制 |

**优势**：信息结构与“速度交错＋AP＋概率命中＋五格控制区”严格对应；可在少量UI组件下提供充分战术判断。

**劣势和风险**：1280×720 HUD在640×360低分辨率世界画布上如何显示清晰中文，需要实验；底部技能按钮较多可能挤占战场；多目标预览以及借机风险可能使操作信息过载。解决策略是折叠情境面板、只显示当前操作相关信息，不让UI长期占满屏幕。

**置信度**：Godot 4.x的CanvasLayer/Control/Container足以实现此HUD架构——**高**（有官方文档支持）。推荐布局、快捷键和预览层级的实际好用程度——**中**（需要玩家操作测试）。具体UI字体大小、图标尺寸和手机/手柄适配——**低**（尚未确定发行平台与字体审美）。

### 23.12 本版决策记录与下一步

- **【已定】v1.8：武学特效 B「适度写意」。** 不更改技能数值与范围。
- **【建议】**HUD采用顶部行动队列、主要地图、底部命令栏、右侧情境预览。

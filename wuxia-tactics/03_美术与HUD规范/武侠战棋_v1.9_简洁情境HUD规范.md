# 武侠战棋 v1.9 简洁情境型 HUD 规范

**正式决定**：B简洁情境型；命中率/命中后伤害/控制区借机攻击风险按需显示。原型按Godot 4.x PC键鼠操作建议制作。


### 24.1 本版正式决策【已定】

1. **选择B：简洁情境型HUD**，不采用“所有角色属性、战术提示和详细说明同时常驻”的密集界面。
2. 顶部常驻行动顺序和当前行动单位，底部常驻当前角色气血、AP、内力和武学快捷指令。
3. **命中率、命中后伤害、状态变化和反击/借机风险按需显示**：例如悬停目标、选中技能、预览移动路径时显示。
4. 技能长说明、状态详解、历史战斗日志原则上折叠；但**足以避免误操作的关键危险提示不能被藏进深层菜单**。
5. 界面形式不改变任何已定规则：速度交错、6AP/回合（暂定数值）、概率命中、八向移动、前侧5格控制区、AP＋内力、共用武学谱库、3招式＋1内功＋1轻功。
6. 信息隐藏**不等于影响公开规则信息的可获得性**；命中率、成本和威胁信息都应在确认前获取，任何危险移动都要二次确认。

### 24.2 常驻与情境显示矩阵【部分已定、细节建议】

| 信息 | 触发条件 | 默认表现 | 规则状态 |
|---|---|---|---|
| 当前角色与行动队列 | 始终 | 顶部紧凑头像/文字 | 已定常驻 |
| 气血、AP、内力 | 我方轮到行动 | 底部当前角色资源 | 已定常驻 |
| 3门招式＋轻功＋基础指令 | 当前角色可操作 | 底部快捷栏，不占大侧边面板 | 已定快捷指令常驻；布局建议 |
| 当前RP | 当前角色/目标被关注 | 资源数字或详情 | 建议显式显示，避免反击不可理解 |
| 命中率＋命中后伤害 | 攻击目标合法且被预览 | 小型浮动详情 | 已定按需显示 |
| 技能费用＋施展后资源 | 选中武学并悬停目标 | 浮动详情 | 已定按需显示 |
| 控制区、借机风险 | 鼠标经过可能危险路径 | 路径覆盖＋警告 | 已定按需显示；危险路径须确认 |
| 详细武学与状态描述 | 悬停按钮或详情快捷键 | 浮动说明 | 已定按需显示 |
| 完整战斗日志 | 玩家主动展开 | 收起的侧抽屉 | 已定默认收起 |

#### 视线与交互优先级【建议】

**当前行动单位与AP/内力 > 可达格与危险步 > 武学命中率与命中伤害 > 临时演出 > 美术装饰。**

悬停预览必须在玩家提交不可逆行动之前出现，且不得将“命中后伤害”简写成“必中伤害”。由于采用概率命中，选择技能时给出相应命中率；即使UI上是一个数字，也来自同一规则计算接口。

### 24.3 首个UI交互样机：B1渡口截箱【建议实施】

工程根目录：`WuxiaTactics_HUD_v1.9/`。**Godot 4.x的独立样机，不覆盖既有工程**。

```text
WuxiaTactics_HUD_v1.9/
├─ project.godot
├─ README.md
├─ scenes/Main.tscn
├─ scripts/hud_demo.gd
└─ data/b1_map.json
```

- `data/b1_map.json`：直接从v1.3的12×12 B1地图提取地形和初始单位标签，无需美术资产。
- `Main.tscn`：1280×720布局基准的简单Control场景；程序生成菱形棋盘及标题、操作栏、情境详情。
- `hud_demo.gd`：统一展示选格、移动预览、基于泥地/普通地形的AP路径、危险路径确认和简化命中展示。
- `README.md`：运行、键位、功能范围与未实现项。

**重要：本样机主要用于UI与操作手感测试，不代表已经完成完整战斗系统。** 当前版未实现真实敌方AI、反击扣RP及伤害结算、AOE多目标、轻功路径障碍判定、完整伤害公式、所有内功与状态机制。演示伤害命中不应作为正式战斗平衡依据。所有数值都是可替换测试数据。

**导入方式**：Godot 4.x → 导入 `project.godot` → 打开项目 → F5运行；`1/2/3`三门武学，`Q`普攻，`E`轻功，`F`防御，`R`调息，`M`回到移动，空格结束当前行动，鼠标右键/Esc取消指令；危险路径弹出确认框。

**运行校验范围**：文件结构及JSON数据已通过Python静态校验，但制作该GDD时环境中未找到Godot可执行程序，因此不能声称工程已通过引擎加载和实机运行测试。

### 24.4 交互状态机【建议】

```text
WAIT_TURN
  └─ 玩家行动开始 → FREE_MOVE
FREE_MOVE
  ├─ 悬停合法落点 → MOVE_PREVIEW（路径、AP、借机风险）
  ├─ 点击普通落点 → COMMIT_MOVE
  ├─ 点击危险落点 → CONFIRM_DANGER（确认后提交）
  ├─ 点击武功按钮 → SKILL_TARGETING
  └─ 结束行动 → WAIT_TURN
SKILL_TARGETING
  ├─ 悬停目标 → TARGET_PREVIEW（命中率/命中伤害/反击）
  ├─ 点击合法目标 → COMMIT_SKILL
  └─ Esc/右键 → FREE_MOVE
CONFIRM_DANGER
  ├─ 确认 → COMMIT_MOVE
  └─ 取消 → FREE_MOVE（不扣AP）
RESOLVING
  └─ 规则结算已定、表现完毕 → FREE_MOVE / WAIT_TURN
```

采用有限状态机，`SELECTED_COMMAND`由游戏交互控制器维护；临时浮层只读`PreviewResult`，绝不直接改变伤害/命中判定。

### 24.5 面板布局与适配【建议】

以1280×720作为**原型布局参考**：上方约70px常驻行动队列，下方约135px紧凑状态＋命令栏；中间保持开放战场；悬停详情小卡片在中上方右侧临时出现，无目标时消失。

- 像素世界的640×360为**此前暂定渲染基准**，不是必须把中文字UI全部渲染到这个低分辨率画布。
- 首版先确保中文UI在1080p屏幕下可辨，后续将UI放到独立于世界像素放大的界面层。
- 顶部信息应优先显示**当前行动角色和最近几名后续行动者**，全部队列可以在展开时查看，避免拥挤。
- 临时预览卡不得遮住鼠标目标格：如临近屏幕边缘，改为自动换侧显示。
- 底部指令按钮不应因资源不足而消失，应保持位置稳定但置灰并说明原因。

### 24.6 Godot正式项目模块划分【建议】

```text
BattleScene
├─ BattleGridLogic                     # 网格/范围/控制区，不保存UI状态
├─ BattleState                         # 角色位置/资源/速度队列
├─ BattleResolver                      # 唯一正式伤害/随机/反击结算入口
├─ BattlePresentation                  # 适度写意的逐帧演出，只读战斗事件
└─ BattleHUD (CanvasLayer)
   └─ HUDRoot (Control)
      ├─ TurnQueueStrip (Control)
      ├─ UnitResourceBar (Control)
      ├─ CommandBar (Control)
      ├─ ContextPreview (PanelContainer)
      ├─ ThreatConfirm (ConfirmationDialog)
      └─ CombatLogDrawer (Control)
```

样机为了便于复制与快速调试，将逻辑和显示放在一个脚本。**这只是实验工程的妥协，不是正式游戏架构决定**；正式实现中应拆分并测试共同的Preview/Resolve规则接口。

### 24.7 B1样机验收清单【建议】

- [ ] 打开工程、能够看到12×12菱形地图、敌我人物与行动队列。
- [ ] 不选技能时，仅出现鼠标所指合法位置的移动详情，不常驻大面积技能说明。
- [ ] 在草地移动显示对应AP；泥地实际消耗2AP，封闭墙角不穿越，角色与敌人占格不可穿越。
- [ ] 危险路径触发二次确认；选择取消不会消耗AP。
- [ ] 选武功→悬停目标显示命中率、命中后伤害和资源消耗；Esc或右键取消。
- [ ] 武学按钮资源不足时置灰；选择操作消耗后，状态栏立即刷新。
- [ ] 结束行动只切换当前单位，不出现“整个我方阵营行动结束”的错误提示。
- [ ] 真正运行后复核Godot版本API兼容及字体显示（本次不声称已运行）。

### 24.8 优势、风险与下一步

**优势**：减轻斜视战场的长期界面遮挡，玩家同时能快速掌握AP、内力与行动顺序；信息出现时机与攻防的不可逆决策对齐。

**劣势与风险**：重复悬停导致操作成本，技能常驻条宽度与简洁原则冲突，临时浮层可能遮挡目标，敌方RP和隐藏状态解释不足。原型重点验证这些问题，不单纯打磨色彩或按钮外观。

**置信度**：Godot 4.x的`Control`、`CanvasLayer`、按钮回调与鼠标事件足以支持该架构——高；具体UI信息密度和悬停操作体验——中；当前原型战斗效果的可玩平衡性——低（演示逻辑未完整）。

**下阶段**：先将样机运行并解决任何脚本兼容问题，再从真实战斗状态中拆分UI数据模型、伤害预览和RP借机攻击，最后接回B1的正式战斗系统。

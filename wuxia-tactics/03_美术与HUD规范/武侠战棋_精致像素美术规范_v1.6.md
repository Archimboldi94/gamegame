# 《武侠战棋》精致像素美术规范 v1.6

正式方向：精致像素风；斜45°视觉；探索实时连续八方向；战棋逻辑正方形八方向AP。除美术风格外具体画布尺寸为待测建议。

### 21.1 已确定的美术方向【已定】

1. **整体采用精致像素风格**，统一适用于江湖探索、战棋地图、战斗角色、建筑和环境特效。
2. 与前文一致，采用**斜45°视觉风格**；首版继续以2D菱形等距投影为【建议】实现路线，不引入必须制作的3D模型管线。
3. 美术呈现应支持战棋可读性：角色站位、面向、敌我归属、攻击范围、地形、控制区优先清晰。
4. 江湖探索继续采用**实时连续八方向移动**；像素风仅约束视觉采样和动画形式，不把连续移动改成逐格跳跃。
5. 本章所有具体像素大小、配色、人物头身、帧数与资源数量均为**【建议】**，不是用户已选定的永久规格。

### 21.2 基准画布与菱形瓦片【建议】

| 资源或参数 | 原型建议 | 作用 |
|---|---|---|
| 逻辑渲染画布 | **640×360 px（16:9）** | 720p为2倍，1080p为3倍整数放大 |
| 战棋地面单格 | **64×32 px 菱形** | 等距投影：宽高2:1，匹配v1.5示例 |
| 角色动画帧画布 | **48×64 px** | 角色可能超过单格的视觉高度，但占位仍为1逻辑格 |
| 角色脚底锚点 | **(24,60)**，相对48×64单帧左上角 | 站位、遮挡、选中圈、影子统一以脚底为准 |
| 常见低矮障碍 | 64×48或64×64 px画布 | 占地按单格/多格另外标注 |
| 大建筑 | 多个瓦片模块或独立分层贴图 | 底座、墙体、屋檐、屋顶单独管理 |
| 武学特效 | 尽量以整数像素网格创作 | 与角色和地砖像素密度一致 |

**说明**：64×32菱形单格的宽度表示水平投影跨度，不能把“角色48px宽”直接理解为占据0.75格；角色仍是脚底占据一个逻辑格。世界地图的现有48×30、客栈14×10表示**逻辑编辑尺寸**，不表示玩家逐格移动。

不同资产可以使用更大的透明画布，但像素颗粒尺度应协调，避免近景采用极粗像素、人物却采用高分辨率细线。

### 21.3 人物造型与制作标准【建议】

**方向提案**：先采用偏成熟武侠造型（约3.5—4.5头身）的轮廓作为测试方向；是否改用2.5—3头身的Q版像素角色，尚待下一轮用户选择。

- 角色轮廓首先需要在**1×原生像素尺度**下辨认出剑、刀、枪、拳师等战斗定位。
- 重要装备以轮廓和有限明暗块区分；避免使用过多单像素杂点。
- 同一角色所有动画帧采用统一脚底锚点，不允许每帧重新居中导致人物上下跳。
- 发饰、衣摆和兵器可以略微超出48×64的基础画布，但应统一延伸规则与碰撞方案。
- 战棋单位的朝向属于**八方向逻辑状态【既有规则】**，人物姿态需能让玩家准确区分朝向；临时素材可用箭头增强提示。

### 21.4 动画制作计划【建议】

**原型起步**：
- 主角：`idle`与`walk`，优先完成**4组方向动画**并辅以八方向朝向标记；底层控制仍为连续八方向。
- 战棋角色：优先保证八方向**静态站姿及明确朝向**，然后再补完攻击动作、受击、倒地。
- 动画播放先以8帧/秒附近为手感起点，具体节奏按动作实测；不强行让每种动画都采用相同FPS。
- `walk`初版每个方向可用4—6帧循环；`idle`每方向1—2帧。
- 后续完整目标为**八方向的战斗站姿与主要武器动作**，可视美术预算采用镜像复用；如右手持剑，镜像会造成持剑手变化，需人工修正或设计为非关键细节。

**资源量风险提示**：假设每名角色8方向×（1张待机帧＋6张移动帧），即56张基础方向帧；三名角色仅这些动作便达到168帧，还不包括攻击、受击和特殊招式。因此**先用轮廓占位稿验证玩法**，再决定哪些方向必须独立手绘。

### 21.5 调色与材质语言【建议】

第一章《青崖渡》建议采用低饱和、略带水墨气质的武侠像素风：冷青水面、竹绿植被、灰褐木石与暖黄灯光。不是单色水墨，而是通过有限的色组和清晰的明暗交代地形。

| 用途 | 建议颜色 | 初步HEX |
|---|---|---|
| 深色轮廓 | 墨蓝灰 | `#273542` |
| 屋瓦/岩石 | 石板灰 | `#596777` |
| 竹林 | 竹叶绿 | `#5C8465` |
| 河水 | 青蓝 | `#47778B` |
| 木材 | 灰褐 | `#8B6650` |
| 灯光高光 | 暖琥珀 | `#D4A66A` |
| 土路/宣纸亮部 | 淡沙色 | `#C9B99A` |

- 可围绕这7个主色扩展阴影、中间色、高光与必要的戏剧性强调；**不设置强制的“整款游戏只允许N种颜色”规则**。
- 可使用有限的局部色相变化表现明暗；避免全屏柔焦和明显破坏像素边缘的泛光。
- 同一高度上的地面使用稳定的明暗方向；环境光方向固定，建筑体块更容易阅读。
- 敌我角色不能只依靠颜色区分；另加队伍标记、轮廓/选中圈，照顾色觉差异。

### 21.6 Godot 4.x 像素显示配置【建议，已核对官方文档】

项目设置建议：
- **基础分辨率**：`640×360`。
- **Stretch Mode**：`viewport`，优先先在低分辨率渲染，再放大显示。
- **Stretch Aspect**：`keep`，先固定16:9；若后续支持更宽比例，再评估`expand`。
- **Stretch Scale Mode**：`integer`，防止非整数放大带来的像素宽度不均；Godot 4.2及后续版本提供该模式。
- **纹理过滤**：像素贴图使用`Nearest`（最近邻），可对相关CanvasItem设置`TEXTURE_FILTER_NEAREST`或使用项目默认过滤参数。
- **地图**：Godot 4.x的`TileMapLayer`＋`TileSet`，地面Tile Shape选择`Isometric`。
- **人物**：`AnimatedSprite2D`和统一脚底锚点；遮挡使用以脚底坐标为依据的Y排序。
- **镜头**：不允许连续的任意小数缩放破坏像素颗粒；先使用固定画面比例并测试相机平滑与像素抖动。
- **UI**：中文文字在640×360画布上可能不清晰；首版正文文字不应依赖过小的像素字体，可为UI另设更清晰的字体方案，并实际验证1080p显示结果。

**重要区别**：物理位置仍可以是浮点世界坐标，以保障探索连续移动；需要做的是控制渲染像素落点、相机和图像采样，而不是把人物世界坐标每帧强制锁死到地砖中心。启用像素对齐功能时，应实测摄像机、移动物体和UI是否产生抖动。

验证来源：Godot官方 `Multiple resolutions`、`CanvasItem`、`Using TileSets` 文档（参见本章末尾官方链接）。

### 21.7 战棋画面可读性规范【建议】

像素美术不能牺牲之前已经确定的战术信息。

| 元素 | 呈现规则 |
|---|---|
| 可到达范围 | 单格半透明青色/蓝色菱形覆盖，鼠标悬停边缘明确 |
| 可攻击范围 | 与移动高亮明显不同的色块、边框或纹理 |
| 五格控制区 | 角色选中或悬停时出现威胁提示；**正侧5格**、**背后3格盲区**一致 |
| 面向提示 | 单位脚底明确方向标记；立绘方向与逻辑朝向一致 |
| 命中概率 | UI显示百分比，不让特效遮盖 |
| 当前AP与内力 | 角色周边状态或HUD可见，避免被高建筑遮挡 |
| 遮挡屋顶 | 角色被遮挡时可启用屋顶局部透明或单位轮廓描边 |
| 技能动画 | 不遮挡敌人和地形过久，支持加速/跳过效果的预留接口 |

**像素风不是逻辑格子的替代品**：任意装饰性绘图不得让一个不可通行格看起来可以正常通行，或让可通行区域被无法理解的视觉障碍覆盖。

### 21.8 资源文件夹与命名【建议】

```text
res://art/
├── tiles/
│   └── qingyadu/
│       ├── ground_64x32.png
│       ├── river_64x32.png
│       └── props_tiles.png
├── characters/
│   ├── player/
│   │   ├── player_idle_e_00.png
│   │   ├── player_walk_e_00.png
│   │   └── ...
│   └── enemies/
├── props/
│   ├── inn_roof.png
│   ├── bamboo_tree.png
│   └── wooden_crate.png
├── effects/
│   ├── sword_slash.png
│   └── qi_wave.png
└── ui/
    ├── ap_icons.png
    └── status_icons.png
```

- 使用英文字母、小写和下划线命名；`动作_方向_帧号`可由导入脚本自动整理。
- `N, NE, E, SE, S, SW, W, NW`的方向名称必须在项目中有唯一、明确定义，不可把画面方向和战棋**逻辑**方向混为一谈。
- 贴图导入时保留透明背景；禁止自动缩放到不同尺寸后再混合打包。
- 资产记录至少包括：文件名、逻辑占地格、帧画布、脚底锚点、碰撞形状、绘制层、方向与动画名称。

### 21.9 第一章的最小美术清单【建议】

**不要一次完成全部《青崖渡》地图。** 应先做一间客栈门口和B1渡口截箱的最小可玩美术样片。

| 优先级 | 资源 | 原型要求 |
|---|---|---|
| P0 | 基础菱形地砖 | 普通地、泥地、木栈道、水边至少4组可辨类型 |
| P0 | 主角占位人物 | 连续移动、停下与面向清晰，可先4方向素材 |
| P0 | 战棋单位 | 至少我方1人、敌方1人，有八方向**逻辑**朝向标记 |
| P0 | 障碍 | 木箱、墙/石块，区分遮挡与阻挡 |
| P0 | 战术覆盖层 | 移动、攻击、控制区各自可区分 |
| P1 | 客栈入口 | 可自由走入、触发室内切换 |
| P1 | 两种NPC | 对话、任务提示和交互点 |
| P1 | 简版战斗动画 | 普攻、命中、未命中、倒地 |
| P2 | 竹林与废祠素材 | B1机制通过后再制作 |
| P2 | 武学特效 | 等玩法与范围判定稳定再绘制 |

### 21.10 美术验收测试【建议】

- [ ] 640×360基准像素画布的输出在1280×720、1920×1080下保持规则像素方块，不出现模糊边缘。
- [ ] 64×32菱形地砖首尾拼接，没有错缝、黑线或贴图边缘污染。
- [ ] 48×64角色帧的脚底锚点在动画播放过程中保持稳定。
- [ ] 探索角色可连续平滑移动，且八方向输入速度一致；没有逐格跳跃。
- [ ] 菱形区域点击结果和BattleGrid逻辑坐标一致。
- [ ] 角色、木箱、屋檐Y排序正确；主角遮挡时仍能被发现和选中。
- [ ] 五格正侧控制区、三格背后盲区、AP移动范围、直线剑气范围在像素层清晰可辨。
- [ ] 角色在B1场景以原始1×像素比例可以分辨敌我、兵器与朝向。
- [ ] 控制界面在1080p实际显示器上，中文战斗提示与概率数字能读清。

### 21.11 优势、成本与风险

| 方面 | 优势 | 劣势与风险 |
|---|---|---|
| 像素角色 | 容易形成强识别的武侠轮廓，符合2D项目 | 八方向角色与多兵器动画的逐帧制作成本很高 |
| 64×32菱形地形 | 与已有逻辑网格、可视范围和地形数据兼容 | 斜视建筑需额外处理遮挡、尺寸与拼接 |
| 640×360＋整数缩放 | 像素颗粒清晰统一，易支持常见16:9屏幕 | 小屏和中文字可能不够清晰，需UI专项测试 |
| 共享环境资源 | 可降低探索与战斗重复制作成本 | 同一资源在战棋与探索的碰撞及目标选择方式可能不同 |
| 精致像素风 | 小体量也可能拥有鲜明美术气质 | 精致并不等于省工；逐帧动画、建筑模块化是主要成本 |

**置信度**：
- Godot 4.x对菱形瓦片、最近邻过滤和整数缩放的支持：**高**（官方文档可验证）。
- `640×360`、`64×32`和`48×64`作为首版像素规格的适用性：**中**（需基于玩家所选人物比例制作样片）。
- 八方向动画产能是否符合个人独立开发时间预算：**低**（缺少实际美术生产速度数据，不给出百分比）。

### 21.12 未决定与下一步

- **下一项需要用户确定**：人物比例，偏成熟写实的约3.5—4.5头身像素武侠，或更Q版的约2.5—3头身像素武侠。
- **待制作测试后确定**：精确帧尺寸、镜头缩放、具体动画帧数、阴影样式。
- **其他保留**：探索是否奔跑、屋顶透明规则、第一章剧情是否沿用《青崖渡》、战斗出现时是否直接切换独立场景。
- **建议的下一技术阶段**：建立一个仅含地砖、主角、木箱、NPC和鼠标选格的Godot像素表现原型，再进入B1的战斗特效制作。

# 《武侠战棋》v1.7 美术制作规范（独立工作稿）

**已定**：精致像素风、斜视地图、偏写实约3.5—4.5头身人物；实时江湖探索和八向网格战棋共用视觉风格。具体帧数、颜色和制作包为建议。

本文对应完整GDD v1.7第22章，用于分配美术工作和制作资产验收。



### 22.1 角色比例及总体视觉方向【人物比例已定】

**【已定】偏写实的修长武侠人物，约3.5—4.5头身，不采用Q版造型。**

- 人物身高、躯干和肢体比例偏成熟。强调线条、动态、重心和兵器轮廓；不追求现实人体的七八头身比例，因为原型48×64像素画布不足以稳定呈现那样的细节。
- **统一造型语言【建议】**：衣饰具有中国古典武侠识别特征，但避免每位角色堆满披风、饰带和华丽纹样。优先保证站立、移动、攻击和受击时的辨识度。
- **视觉服务战术【必须遵循既定玩法】**：八方向逻辑面向、兵器、控制区与攻击方向不得被衣袍、光效或建筑遮挡成不可理解的状态。
- **与前版保持一致**：精致像素；斜45°等距视觉；小型区域实时探索；战棋逻辑八方向网格，AP移动与前侧5格控制区不变。
- **原型参数【建议】**：角色显示高度52—58px，头高约12—15px，对应约3.7—4.4头身；单方向角色帧使用48×64px作为常规画布，脚底锚点(24,60)。长枪、飘带、跳击等超出画布的动画可使用更大的帧矩形或独立武器贴图，统一保持脚底锚点不变。
- 武器、发束与衣摆的夸张程度应体现在剪影和动作弧线上，而不是随意扩大头部比例。

#### 22.1.1 形态语言及颜色【建议】

| 项目 | 人物美术约束 | 反例与风险 |
|---|---|---|
| 头身 | 主体约3.5—4.5头身，四肢修长 | 头过大导致Q版化，或头过小导致表情不可读 |
| 剪影 | 剑客轻、枪客高、拳师稳，三者重心不同 | 换一把武器就像同一个模型，会削弱角色差异 |
| 线条 | 以成片像素色块塑造轮廓、衣褶和头发 | 随机散点、高频噪声使人物碎裂 |
| 服装 | 腰带、护腕、衣领、发束优先，纹样克制 | 过多流苏与复杂纹饰会抬高每帧成本 |
| 方向 | 角色逻辑与贴图方向均有明确映射 | 单凭水平镜像会颠倒持剑手、肩甲或发型 |
| 阵营 | 颜色只是辅助；配合脚下标记及轮廓差异 | 仅用红蓝配色识别敌我不够可靠 |

### 22.2 三名原型角色设定【建议，人物和服饰均可调整】

沿用第一章原型的三种战术定位：剑客（A）、枪客（B）、拳师（D）。这些是便于制作验证的**临时造型方案**，并非正式剧情角色或必须使用的角色性别设定。

| 角色 | 头身和轮廓 | 服饰/主色（建议） | 标志性站姿和动作 | 战术读取 |
|---|---|---|---|---|
| 游侠·剑客 | 约4.0头身，窄肩、腰收、下摆开叉 | 青灰短披风、灰蓝束袖长衫、深色皮带，刀剑金属低明度 | 半侧身，前脚虚点地；执剑手自然下垂，出招瞬间拉出窄长弧 | 轻巧、侧袭、回锋、精确攻击 |
| 守线·枪客 | 约4.3头身，纵向高、肩背挺直 | 深褐劲装、暗青护腕、极少量朱红枪缨 | 长枪竖斜持，待机枪尾落近脚边，反击短促前刺 | 距离控制、控制区、守卫地形 |
| 通脉·拳师 | 约3.8头身，上身稍宽、重心低 | 浅灰练功袍、深竹绿束带、拳腕缠布 | 双拳护中线，手臂前曲，发招时躯干先旋后推掌 | 点穴、近身控制、击退 |

**敌人造型【建议】**：劫客以灰褐短装与弯刀/短棍形成不对称轻甲剪影；废祠守卫以深灰布甲、厚护肩形成更重的方形剪影；首领通过宽帽檐/独特肩衣及武器轮廓与杂兵区分。无需首版给每种敌人绘制完整独立动画套件，优先复用相同骨架比例下的动作资源。

**角色表情方案【建议】**：探索对话优先使用静态半身像或头像展示情绪；战棋单位的小像素角色不要求靠面部实现复杂表演，以体态、朝向、停顿和少量色块变化呈现反应。

### 22.3 场景美术：第一章《青崖渡》【剧情场景沿用原型建议】

#### 22.3.1 统一色彩、光照与地表分层

- 基础环境延续v1.6的墨蓝灰、灰石、竹绿、青蓝水面、暖木及琥珀色点灯。整体低饱和，重点角色和交互物可以使用少量更高亮的暖色。
- 建议固定环境主光来自**画面左上方**，建筑、箱子和人物遵守统一受光方向；像素阴影采用有限台阶，不使用过度模糊的软阴影。
- `Ground`（地表菱形瓦片）、`LowProps`（脚边障碍与栏杆）、`Actors`（人物与NPC）、`Foreground`（屋檐、树冠等前景遮挡）、`CombatOverlay`（格子/范围高亮）、`UI`（战术信息）分别维护。
- 与人物交互的地面逻辑始终以脚底为准；房屋高大的绘制贴图不自动意味着相同形状的地面碰撞区域。
- 场景美术可制作“局部遮挡时屋顶透明”的演示版本，但**是否采用透明屋顶仍为【待定】**。

#### 22.3.2 各场景的辨识设计【建议】

| 场景 | 视觉重点 | 主要模块 | 交互/战术对应 |
|---|---|---|---|
| 听雨客栈（室外＋室内） | 灯笼、木格窗、深色屋瓦、温暖室内 | 墙角、门洞、桌椅、楼梯假景、柜台、灯笼 | 可自由靠近NPC；门口切图与屋檐遮挡测试 |
| 青崖渡口（B1） | 水面与木栈道的冷暖对照，浅雾、货箱 | 4组地砖、木板过渡、货箱、栏杆、浅水波 | 箱体阻挡、泥地2AP、有效射线与站位 |
| 竹林旧道（B2） | 稀疏竹林、石径、断墙、斑驳暗影 | 竹干、竹冠、石径、矮墙、沟壑、遗匣 | 轻功越障、绕背、控制区脱离 |
| 废祠（B3） | 破损檐角、残柱、石碑、冷灰祭台 | 墙体、石柱、神龛、陷阱、渡簿、箱车变体 | 多线进攻、掩护、陷阱与路线分歧 |

**制作次序**：先完成客栈门口+1小段渡口栈道，不同时完成4张场景精修。B1逻辑战斗稳定后，再将同一水边与箱子材质复用到其他区域。

#### 22.3.3 场景空间与可读性要求【建议】

1. 探索屋檐、树冠和竹林前景可以遮住部分上半身，但任何时刻玩家至少能通过角色脚底位置、轻量轮廓描边或局部透明判断自身位置。
2. 战棋中玩家选中的单位头顶和脚底要优先于装饰层读得出来。相机不以“漂亮构图”为由隐藏行动区域及重要敌人。
3. 高大的竹冠、屋顶可作为视觉层，不影响下方逻辑障碍判定；断墙、货箱的占位必须与逻辑数据一致。
4. 所有可交互物使用统一的“可互动”提示语言（轻微亮度差、图标或地面圈），而非每类独立发明一套指示效果。
5. 关键地形先以**没有光效和阴影的基底版本**测试认路，再增加装饰。

### 22.4 动画方向与资源规模【建议】

**八方向逻辑朝向已定**，但**八方向动画全部独立绘制尚未确定**。首版遵循“先保证朝向正确，再提高动画精度”的策略。

| 模式 | 最小必需动画 | 原型帧数 / 节奏建议 | 优先级 |
|---|---|---|---|
| 探索 | idle、walk、interact | 4方向idle每向1—2帧；walk每向4—6帧，约8—10FPS | P0 |
| 战棋 | idle、move、melee_attack、hit、miss、down | 八方向逻辑面向提示；先做4方向动作变体，重要招式再扩展 | P0 |
| 战棋反应 | reaction_attack、block、hit_reaction | 与普通攻击共用大部分动作，反击起手和提示独立 | P1 |
| 武学 | cast、release、recover、受击位移 | 在通用角色动作上叠加可复用技能特效 | P1 |
| 叙事 | 对话头像、表情切换、转身 | 静态为主，避免制作冗长场景动画 | P2 |

**帧数核算示例（并非项目工时估算）**：1名角色的4方向待机1帧＋4方向行走6帧 = 28个源图帧。3名角色就是84帧，**还未包含攻击、闪避、倒地、反击**。若采用8方向待机1帧和行走6帧，则每名56帧，3名168帧。资源表应分别记录**帧图数量、是否共用、最终图集数量**，防止工时被低估。

**镜像复用原则**：左右镜像可用于过渡，但带有明显单侧武器、剑鞘、肩甲或不对称发型时不得默认一键镜像就是正确。关键朝向至少保持兵器持握可信；不影响操作时允许细节简化。

### 22.5 战斗动画流程与机制时间轴【建议】

战棋的**行动结算与美术演出必须分离**：

- `BattleResolver`按既定规则进行AP/内力支付、一次概率命中判定、命中后伤害/状态/位移/反击/胜负结算，产生明确的`CombatEvent`序列。
- `CombatPresentation`消费事件序列，播放人物动作、移动、音效和像素特效；不在伤害动画的某一帧再次随机计算命中。
- 动画表现上的“击中帧”只决定**何时显示已结算的伤害和命中反馈**，不能使业务逻辑出现先后不一致；视觉效果不能添加未声明的AP消耗、距离或反应次数。
- 游戏输入在结算与关键过渡时受控锁定，播放结束后恢复；允许后续增加加速动画，不允许直接改变战斗结果。

#### 22.5.1 普通攻击演出（测试节奏）

| 时点（秒） | 动作 | 画面信息 |
|---|---|---|
| 0.00—0.10 | 转向、蓄势、武器后拉 | 施术者脚底仍锁定格心 |
| 0.10—0.22 | 出手，兵器运动弧 | 方向与合法目标一致 |
| 约0.22 | 命中帧/落空帧 | 命中显示已结算伤害与受击；未命中显示“未命中”，不闪出虚假伤害 |
| 0.22—0.40 | 收势、角色回到站姿 | 若触发反击，则进入新的反应事件 |

**反击特例**：攻击直接目标，即使本次落空也可能触发其一次自动反击；是否触发依赖此前GDD的合法射程、正侧5格、RP、存活等规则。反击动画是后续事件，不允许自我递归出新的反击演出。

#### 22.5.2 动作类型【建议】

| 动作 | 身体运动要点 | 战术反馈 |
|---|---|---|
| 剑客普通攻击 | 侧身跨半步，快速直刺，回身 | 攻击朝向明确；位移仅为视觉偏移，不改战棋格子 |
| 枪客普通攻击 | 先压枪、再沿直线突刺，短回收 | 射程和直线约束清晰，不能造成误以为可穿墙的错觉 |
| 拳师普通攻击 | 掌根从腰侧发出，身形短促前倾 | 近身冲击感；不自动击退，除非对应招式有击退规则 |
| 自动反击 | 起手短、动作更快、武学特效较少 | 反击者RP图标熄灭，且不会连锁反应 |
| 格挡/护势 | 稳住下盘、抬臂或气流收束 | 格挡显示护甲符号，护势显示轻量气罩，两者不可视觉叠加 |
| 闪避/未命中 | 有限制的躯干侧移或兵器擦身而过 | 仅表示本次概率命中检定失败，不新增独立闪避判定 |
| 击退 | 脚底跨格轨迹明确，落点格亮起 | 位移结果来自逻辑结算，不能由动画自行决定落点 |
| 倒地/退场 | 短暂停顿后倾倒或消隐 | 降低遮挡，清楚表达单位失去行动能力 |

### 22.6 武学特效：招式到视觉语言的映射【建议】

每种武学的“亮点”应来自攻击形状、速度、击退轨迹和目标变化，**不是简单放大爆炸面积**。原型特效尽量重复使用核心粒子、冲击圈、残影和地面贴花四类基础素材。

| 武学/状态 | 建议像素特效 | 必须表达的战术信息 | 常见风险 |
|---|---|---|---|
| 破风剑 | 细长冷白剑气沿合法格心逐段闪现，末尾短促消散 | 直线3格穿透多目标，障碍处停止 | 剑气画得太宽被误解为扇形 |
| 回锋剑 | 小范围剑弧、角色残影、后撤落点圈 | 命中或攻击后的后撤必须按招式实际规则演出 | 视觉后退若未被结算，容易造成假位移 |
| 横江刀 | 宽而短的金灰色扫击弧，按方向覆盖三个邻格 | 面前横扫多个格子 | 弧线伸入未命中的格子造成误判 |
| 震山掌 | 掌前一圈低饱和土金震波，目标脚下出现退格轨迹 | 只击退合法目标1格 | 撞墙特效暗示额外伤害但机制未提供 |
| 截脉指 | 微小青白指光，目标胸前短闪，脚底脉络纹理 | 目标下一行动AP减2，状态图标可持续追踪 | 观众看不懂控制效果，只看到闪光 |
| 守关式/护势 | 身体周围一层短暂聚气描边，身边保留小图标 | 下一次受击减伤25%，只存在一层 | 长时间大气罩挡住角色与攻击路径 |
| 燕行步 | 起点一帧残影、短线轨迹、落点两帧碎风 | 可跨低障碍、最多3格、免借机攻击 | 残影轨迹穿墙，误导为可穿任何障碍 |
| 踏雪步 | 脚下浅白碎点与短促护势纹样 | 2格位移及获得护势 | 与普通燕行步视觉混同 |
| 归元诀 | 自身内力图标附近微弱循环青绿光点 | 自身行动开始内力恢复 | 把被动恢复表现成长时间施法 |
| 苍松功 | 脚底短促松针状青影，护势UI亮起 | 达条件获得护势 | 绿色特效与治疗视觉混淆 |

#### 22.6.1 通用视觉字典【建议】

- **攻击路径**：细线/剑气，随方向转动，严格跟随逻辑范围；色调以亮灰、青白为主。
- **身体护势**：贴身小范围轮廓＋UI状态，不使用覆盖整格的不透明色。
- **内力恢复**：细小向心粒子、内力条变化；勿误认为回血。
- **破甲**：目标护甲图标出现裂纹；不把“破甲”表现成流血伤害。
- **破势**：防护光效先碎裂，之后出现伤害数字，符合结算先后。
- **借机攻击预警**：移动路径旁有风险图标、红橙色小标，不与技能AOE红区混成一片。
- **未命中**：目标局部移动或刃光擦过，不出现伤害数字；不追加独立闪避骰。

#### 22.6.2 特效预算与视觉纪律【建议】

- 首个可玩原型只需要**普通攻击、命中、未命中、自动反击、移动范围、五格控制区、燕行步、破风剑**的简版效果。其余技能在P1/P2制作。
- 默认普通招式演出约0.3—0.6秒；特效停留应短于遮挡整张战棋界面的时长。剧情Boss特效可另行设计，但不能改变逻辑命中范围。
- 尽量采用透明像素序列帧和Sprite2D纹理序列；是否用`GPUParticles2D`待评估像素尺度与平台兼容性后确定，不因特效“更炫”强制引入高复杂管线。
- 相机震动属于可关闭的辅助表现；原型中若使用建议限制在轻微短促的1—2显示像素，**UI不参与摇晃**。不允许通过过度屏幕闪白、快速闪烁来替代动作设计。
- 在技能效果播放前必须有明确的**范围预览**，命中/击退/封招的数值或状态变化应在演出后继续可见。

### 22.7 Godot 4.x 美术播放架构【建议】

Godot官方文档支持`AnimatedSprite2D`使用`SpriteFrames`加载逐帧图像或图集；`AnimationPlayer`可处理更复杂的位置、透明度、属性动画；`TileMapLayer`/`TileSet`支持菱形瓦片及Y排序参数。它们提供技术可行性，但具体项目结构仍需要本地运行验证。

```text
UnitVisual (Node2D; origin at feet)
├── Shadow (Sprite2D)
├── CharacterSprite (AnimatedSprite2D)
├── WeaponVisual (Sprite2D / AnimatedSprite2D)
├── AnimationPlayer
├── StatusMarker (Node2D)
├── ReactionMarker (Node2D)
├── GroundSelection (Node2D)
└── VisualEffects (Node2D)

BattleScene
├── BattleGridLogic (Node)         # 格子、AP、命中、RP、ZoC、状态
├── BattleGround (TileMapLayer)   # 等距地形表现
├── UnitsYSort (Node2D)           # 统一以脚底排序
├── CombatPresentation (Node)    # 读取战斗事件并播放动画
├── RangeOverlay (Node2D)         # 移动、技能范围、五格控制区
└── BattleHUD (CanvasLayer)       # 行动队列、AP、内力、命中预览
```

**必须明确分离**：
- `logical_facing`：规则里的八方向编号；计算5格控制区、背击角度与反击合法性。
- `visual_facing`：将逻辑方向映射到菱形地图上的屏幕朝向；用于选择角色帧。探索时人物朝向则依据连续移动的**屏幕输入向量**显示。
- `logical_tile`：一个单位的格坐标；角色动作的身体前倾不应修改该字段。
- `visual_offset`：动画过程中的局部像素偏移；动画结束必须复位。
- `hit_result`：唯一的规则层概率判定结果；动画不额外掷骰。

**事件示例【建议数据结构】**：

```json

  "target_id": "raider_1",
```

示例字段是**事件演出接口草案**，不是Godot自带API或可直接运行的战斗代码。反击若触发，应另输出事件`reaction_attack`，由呈现层顺序播放，禁止在动画脚本中临时决定是否反击。

### 22.10 验收标准与风险

- [ ] 三名原型角色符合约3.5—4.5头身；不出现头部过大或明显Q版化。
- [ ] 在640×360原生显示尺度下，无职业标签也能区分剑客、枪客、拳师。
- [ ] 角色左右镜像时不出现明显武器持握错误；必要时专门补绘非对称帧。
- [ ] 脚底锚点在待机、行走、出招、反击、受击、落空之间保持一致，未改变逻辑占格。
- [ ] 斜视地图点击逻辑格正确；前侧5格控制区和背后3格盲区能正确投影显示。
- [ ] 一次攻击只有一次命中判定，视觉命中/未命中与规则结果一致。
- [ ] 反击演出不会出现无RP反击、多次反击、反击套反击。
- [ ] 燕行步越过低障碍的动画没有暗示穿越实体墙，击退落格没有超出规则允许范围。
- [ ] 在道具、屋檐、竹子遮挡下，玩家仍能识别自身人物、目标位置和行动提示。
- [ ] 相机缩放和像素显示测试不造成明显边缘模糊；中文字、行动队列和命中预览可读。

| 方面 | 优势 | 风险及应对 |
|---|---|---|
| 偏写实修长比例【已定】 | 人物武侠气质鲜明，兵器站姿更有区别 | 像素画布过小时脸部细节不足；优先使用剪影和独立对话头像 |
| 斜视像素场景【已定】 | 建筑与江湖道路层次丰富，可沿用现有战棋格子逻辑 | 遮挡、动态深度排序复杂；建立脚底锚点和视觉层次规范 |
| 少量动画＋通用VFX【建议】 | 产出快，容易先完成真实可玩原型 | 动作重复感；后续以最常见动作和关键武学优先补帧 |
| 规则与表现分离【建议】 | 不受动画长度影响，易回放战斗和测试概率判定 | 事件接口设计需谨慎，不能让动画中途改变真实结果 |

**置信度评级**：偏写实人物比例与现有斜视武侠定位的风格一致性：**中**（审美和实际样张需要验证）；Godot逐帧动画、图集和菱形瓦片所需引擎基础能力：**高**（官方文档支持）；目前尚无美术产能与机器目标数据，具体美术总工作量、性能和主角帧规格的置信度为**低**。

### 22.11 下一项待决定

**武学特效的整体夸张程度**（目前未确认）：
- A. **写实克制**：刀光很短、内力近乎不可见，以动作本身为主。
- B. **适度写意【推荐讨论】**：剑气、残影、点穴纹理清晰可见，但特效严格服从格子范围与HUD。
- C. **高武夸张**：大范围光效、显著内力外放与多段镜头强调；但增加制作成本和战斗信息遮挡风险。

三种方案只影响特效表现**强度**，不自动改变任何招式的实际射程、AP、内力消耗或伤害。
